## Findings

### 1. The 0.10 default loses a genuine merge on held-out data — the important one

DR-259 calibrated the threshold on #248, #232 and #144. This run is a fourth
task file it was not calibrated on, so applying the DR's own method to it is a
held-out test. Method identical: `description + observable_behavior` embedded
with `voyage-3.5-lite`, raw cosine, labels taken from the model's own
`same_requirement` verdicts rather than from reading distances — so it is not
subject to the DR's stated contamination limit.

46 pre-link obligations, 1,035 pairs, 12 model-confirmed merges.

| threshold | pairs asked | merges kept |
|---:|---|---|
| 0.05 | 1.1% | 9/12 |
| 0.08 | 1.7% | 10/12 |
| **0.10** | **2.1%** | **11/12** |
| 0.15 | 3.4% | 11/12 |
| 0.20 | 5.4% | 11/12 |
| **0.23** | **6.7%** | **12/12** |
| 0.30 | 13.3% | 12/12 |

The merge lost at 0.10 sits at **0.2257**, and it is genuine beyond argument —
the headline requirement merging with its own constraint restatement:

```
[obligation-distance-threshold-exclusion]
  description: Pairs whose distance exceeds the threshold are not sent to the model.
  behavior:    A pair with distance greater than the configured threshold is omitted
               from model submission.

[task-01-obligation]
  description: Obligation pairs that are too dissimilar to state one requirement are
               not asked about.
  behavior:    Pairs whose distance exceeds the threshold are not sent to the model,
               so they are not asked about.

model: same_requirement=true — "effectively the same requirement ... Same truth
conditions and same test."
```

DR-259 put the farthest genuine merge across four sweeps at **0.0938**. Here it
is **0.2257** — 2.4× further out. The separating band the DR found does not
generalise to this task file. The cause is visible in the pair above: the two
obligations paraphrase each other *across levels of abstraction*, one stating
the requirement and one stating the mechanism, and that gap is much wider in
embedding space than the near-verbatim restatements the calibration sample was
dominated by.

**This is precisely the risk the DR flagged in its own Limits section** — three
task files, all this repo's own, labels not independent. It is confirmation of
that limit, not a surprise.

Consequence at 0.10 is mild in kind and bad in placement: one redundant
obligation, which is the safe under-merge direction, but landing on the
**headline** requirement. It does not lose requirement content.

### 2. Three composite obligations survive as redundant, and linking cannot merge them

The final breakdown carries 35 obligations for 33 requirements. Derivation
restates much of the mandate under `task-01`, and linking correctly merged 11 of
those restatements away. Three survive:

- `task-01-obligation-2` — "Pairs are filtered for asking based on cosine
  distance between their embeddings" (spans `task-01` + `constraint-02`)
- `task-01-obligation-4` — "The threshold used for filtering is configurable and
  defaults to 0.10" (spans `constraint-05` + `constraint-06`)
- `task-01-obligation-15` — under `constraint-17`, adds "exercises the change"
  to "tests issue no live model calls"

All ten pairs involving these were asked and denied, with defensible reasons.
**Linking is working as designed.** A composite spanning two requirements can
never have identical truth conditions with either part, so the strict sameness
test correctly says no — and the composite then survives forever. The defect is
upstream in derivation, which produced an over-broad inferred obligation; it is
#223/#210 shape, not #242 (nothing was blocked by an inconsistent cluster).

Note `task-01-obligation-15` carries a `task-01-` id prefix while owned by
`constraint-17`. Cosmetic, but the id asserts a provenance that is wrong.
