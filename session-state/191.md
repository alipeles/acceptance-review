## What the branch delivers

Discrimination was one model call carrying every criterion's every defect
verdict. It is now two calls, each partitioned by criterion with its own size
control folded into the hashed request:

- **enumeration** — names plausible defects from the criterion text and the
  changed code. Sees **no test, in any form**. That is what makes "adding a test
  leaves this criterion's defects unchanged" true by construction: the request
  bytes are identical, so the transcript replays.
- **verdict** — judges each named defect against the mapped tests, the changed
  code, and (since `492abad`) each test's **source**, not just its extracted
  assertions.

Defects are joined across the two calls by a positional id
(`<criterion>::d<n>`), never by wording, because the wording is what moves.

## The four measurements, and what they establish

All in `docs/experiments/191-discrimination-partition/`, reproducible with
`retake_baseline.py` (replays from cache; only `--record` costs money).

| | ec diffs | perturbation | caught / not caught |
|---|---|---|---|
| pre-change (one call) | **2** | 1 of 21 | **114 / 0** |
| split, no code in verdict | 16 | 13 of 21 | 111 / 30 |
| code restored | 13 | 12 of 21 | 82 / 52 |
| + test source | 17 | 13 of 21 | 91 / 43 |

**The one solid result: the pre-change judge was a rubber stamp.** It answered
`would_be_caught: true` to 114 of 114 defects across three runs, with exactly two
defects per criterion every time. Its low variance was the stability of a
constant function. `lower variance than the pre-change baseline` — #191's stated
Acceptance — is therefore satisfiable by re-blunting the judge, and should not be
used as written. **That is an open question for the human, not something to
quietly reinterpret.**

**Three hypotheses tested and not supported:** information starvation on the diff
(explains about a fifth), missing test source (explains none), and "the verdict
instability is mapping's fault" (at least partly decomposition's — see below).

**Not raw model nondeterminism.** One real verdict prompt issued three times at
temperature 0 with a fixed seed returned byte-identical verdicts. The inputs
move; the judge does not, on identical input. (One batch, an easy one.)

**Prompt caching works.** Measured live: 84–93% of each verdict request is served
from the provider's prompt cache, because both prompts put the invariant code
block first and the per-batch criteria last. That ordering is load-bearing and
tested. Caveat: measured on `openai/gpt-5.4-mini`; Anthropic-family models need
explicit `cache_control` breakpoints, **not done**.
