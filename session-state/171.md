## What two parked experiments give M8.4, and what they want from it

Both are in `docs/experiments/`, both reached a result, and both stop at the same
wall: a small set of pairs where a static signal and the pair judge disagree,
which nothing static can adjudicate. Injection is the adjudicator. Read
`docs/experiments/README.md` first; it is the index and says which experiments
are settled and which two are parked here.

- **Test selection for injection.** `coverage-prefilter/FINDINGS.md` argues the
  coverage map is the right way to pick which tests to run under injection — a
  test that never executes a line cannot fail on a mutation of it — at roughly 20
  CPU-minutes and zero tokens against $6.02 of static judging per run. Its 9 of
  48 judge-everything fallbacks (documentation defects, absence defects) stay on
  the fallback.
- **A ready-made first case list.** 43 pairs where coverage and the judge
  disagree, plus 3 from `prefilter-committee/`. Adjudicating them measures
  pair-verdict accuracy against ground truth **for the first time** — #315's
  human-reviewed labels are the only current proxy.

Neither runs from a clean checkout without external inputs; each names what it
needs and stops with a sentence when it is missing. See
`prefilter-committee/paths.py`. Both also need `pip install coverage`, which is
deliberately not a project dependency.

## The suite shrank on purpose, 2026-09-01 — 1311, not 1636

Two tests were parametrised over every committed file in `dogfood-logs/`, so
every dogfood run added two tests forever: 338 cases, 20.7% of the suite.
`tests/requirement/corpus.py::committed_task_files` now keeps **one file per
distinct markdown shape**, and 169 files turn out to hold **five** shapes — 97
identical, 65 more differing only by inline code. So 338 cases became 10, and
three new tests pin the filter.

**Do not read the drop from 1,636 to 1,311 as tests going missing.** The
signature is built from markdown-it rather than from `parse_task_file`, on
purpose: these are tests *of* that parser, and deriving the case list from it
would let a parser regression shrink its own test set.

## One thing PR #328 shipped that is not tuned

`DEFAULT_TESTS_PER_BATCH = 4` in `defects/pair_mapping.py` is the smallest step
that gets a measured effect, not a tuned value. `DEFAULT_PAIR_BATCH_SIZE` still
caps judgements per response at 40, so more tests per call means fewer defects
offered with each — and that trade was never varied. The pilot compared 1 test
per call against 2–3, on calls carrying at most 15 judgements where production
carries 40.
