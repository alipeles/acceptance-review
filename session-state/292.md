## The wrinkle this has to solve

`judge_discrimination` returns **defects**, not a rating. The rating is
`strength.py::classify_strength`'s deterministic reduce over those defects, so
"a judgement that alters a rating" is only knowable after the reduce. Plan:
apply the reduce to the fresh discrimination for the one criterion, compare with
the stored `evidence_class`, and reject there. The reduce is pure and importable,
and that reader is exactly where the mandate wants the rejection.

## The plan, as approved at Gate 1

- **New module under `evidence/`** computing, per criterion, a typed list of
  changes to its dependencies, each with a stable id. File-granular for now.
- **`evidence/discrimination.py`** — `judge_discrimination` gains per-criterion
  *anchors* (stored `evidence_class` + that criterion's dependency changes).
  `_render_prompt` grows an anchor block for anchored criteria only.
  `_ObligationDiscrimination` gains `rests_on`. `allowed` gains a `rests_on` key.
- **The rejection lives in the reader.** Apply
  `classify_strength([obligation], its tests, [fresh discrimination])[0]` and
  compare with the stored class. If it moved and `rests_on` names nothing that
  criterion was given: **discard the fresh discrimination and keep the prior
  one.** Do not force the class afterwards — the class is derived from defects,
  and forcing it leaves the two inconsistent in review state.
- **`pipeline.py`** builds anchors from the prior review and threads the
  `UnusableAnswerLog`. **`report.py`** — verify the rejection actually surfaces.
- **Tests**, including a wiring test that the pipeline passes anchors. The
  repeated hole in this repo is a good helper the pipeline never calls.

**`constrain` cannot carry the whole guard.** It takes a flat field→ids mapping,
so the `rests_on` enum can only be the *union* of change ids across all criteria
— a criterion could name another criterion's change and satisfy the schema. The
per-criterion check therefore has to be in the reader as well. The enum is a
coarse guard, not the guard. This is fine and is where the mandate wants it.

## Enforcement, all of which already exists

`supplied_ids.constrain` puts the supplied change ids into the response schema as
an enum, so an unsupplied change is *unrepresentable*; `scan` catches a provider
ignoring the enum; `UnusableAnswerLog.record` + `unusable_answer_finding` is the
"a rejected judgement is reported" half.
