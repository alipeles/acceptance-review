## The defect that will make Gate 2 hard — expect it, do not chase it

**#182: mapping is unstable under a purely additive change**, and it is now
measured. #292's Gate 2 runs 1 and 2 had the same task file, both used
`--continue`, and their obligation blocks were **byte-identical across 29 lines**.
Only `tests/` differed, in two files. One obligation went from four mapped tests
to **none** — and none of those four was modified, renamed or removed; all four
live in files absent from the diff. Filed with that evidence as a comment on #182.

**This bounds #293 directly.** #293's Acceptance says a criterion whose mapped
test set gained or lost a member is judged again. If membership churns on its
own, criteria are re-judged for no reason — the exact cost #293 exists to remove.
#293's issue recommends comparing against the **current** mapped set anyway, with
#292's enforcement as the backstop. That recommendation predates the measurement
above; weigh it again rather than inheriting it.

**#242: twin obligations split the evidence between them.** The task-file
convention states each rule as a Constraint and mirrors it as a Completion
expectation. The linker leaves the pair unmerged and the mapper attaches the
covering test to one twin, so the other reports `unsupported`. #292's Gate 2
never came back clean for this reason across three rounds.

**#292 was merged with Gate 2 not clean, deliberately**, on the judgement that
both are report-quality tool defects that no change in the PR would fix, and that
every rule in the mandate had a test that fails if the rule is absent. Expect to
make the same call, and **get it approved rather than assuming it**. Do not
reword `current-task.md` repeatedly to chase a clean gate — #292 tried three
rounds and the bare obligation just moved between twins. The standing rule is
*fix the wording, never the output*; a reword chosen to move the mapper is the
forbidden kind.

## Do not rediscover

- **`--continue` on every gate re-run**, Gate 1 and Gate 2. Without it nothing
  carries forward and the obligation set moves for reasons unrelated to the edit.
  #292's chain ended at `e6c1f946e47d5280`.
- **The first Gate 2 run continues the last Gate 1 run.** #292 slipped once,
  continuing the second-most-recent run; harmless there, but do it right.
- **`ruff` is pinned to 0.16.2 and the pin matters.** On 0.15.x the `BLE` rules
  are not in the default set, so `ruff check .` reports clean on a tree CI
  rejects. This broke `main` for four commits on 2026-08-20. Check with
  `.venv/bin/ruff --version` before trusting a clean local lint.
- **`litellm` must be 1.93.0 in this worktree.** A fresh `.venv` resolves 1.97.0,
  which cannot make a live call at all (`PydanticUserError: 'Message' is not
  fully defined`, surfaced as `APIConnectionError`). Replay mode never notices,
  so CI cannot catch it. `pip install` needs the sandbox off — it hits the same
  TLS wall as `gh`.
- **Gate 2 needs `--mode record`.** Replay is the default and a new diff has no
  transcript, so `check` dies with "no recorded transcript".
- **`docs/DEFERRED.md` is edited concurrently by several sessions**, all
  inserting at the same point just after the template block. Re-read it from
  `origin/main` and re-apply your entry by hand; committing a stale copy silently
  reverts someone else's entries.
- **Committing a dogfood run grows the test corpus.** `tests/requirement/corpus.py`
  globs `dogfood-logs/*/current-task.md`, two parametrized cases per run. The
  suite count rising after you commit a run is correct, not a bug.
- **`tests/benchmark/test_rating_regression.py` fails spuriously while any other
  session has a `git worktree` operation in flight.** All the worktrees in this
  repo share one `.git`, and the signature is

  permitted` — six failures, then 34/34 passing on the same commit once the other
  worktrees are gone. Reported by the #265 session. If you see it, it is not your
  diff; re-run before investigating.

  #265 was at `1437` on its own; both were correct.
- **Save each dogfood run with its exact task file.** #292 nearly filed three
