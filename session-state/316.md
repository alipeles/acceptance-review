## The pre-code verification #316 requires, and its result

**It holds.** Flipping the consumer does not move the new stages' request keys,
so their recorded transcripts replay across the cutover and only the retired
stages' recordings die with them. DR-312's resolved question 5 accepted the
staged-migration re-record cost on this expectation; it does not have to be paid,
and there is nothing to re-present.

Two independent reasons, one read and one measured:

- **Read.** `llm.py::request_key` content-addresses the request — model, messages,
  temperature, response schema, seed, partition, stage controls — with no call
  index or sequence counter, so deleting an upstream stage's calls cannot move a
  downstream stage's key. `request_blocks.assemble` orders blocks by a static
  `BlockKind` enum and adds nothing to a request, so it is stateless across the

  `evidence/discrimination.py` or `evidence/strength.py`; the one `evidence/`

- **Measured.** A probe ran `run_review` twice over one repo — once whole, once

  replaced by a stand-in that raises — and compared the recorded request keys per
  response schema. `_Enumeration` and `_PairVerdicts` each issued one request in
  both runs, with identical keys. Script:
  `<scratchpad>/probe_shadow_survival.py`, reusing the fixtures in
  `tests/defects/test_pair_mapping.py`.

**What this does not cover, and what would break it.** The probe covers removing

## What was built

**`defects/support.py`** is the whole judgement, and it makes no model call.
`derive_support(obligations, defect_sets, verdicts, unjudged)` — every argument a
record a stored `Review` keeps, so any consumer can recompute a rating from the
review it was rendered in. Rules: all defects covered → `strongly_supported`;
some covered → `partially_supported` (true whatever an unknown turns out to be);
none covered and none unknown → `unsupported`; none covered with something
unanswered → `indeterminate`; a reasoned-empty enumeration → `no_plausible_defect`.
A prefilter exclusion counts as a *survives* established statically, not an
unknown — the filter excludes only what it can prove, and reading it as unknown
would make a working filter look like a shedding judge.

**The denominator is stored, not recomputed at render time.**
`Obligation.enumerated_defects` and `covered_defects` sit beside
`evidence_class`, so a rendering cannot disagree with the class it decorates.
`report.py::_denominator` renders "kills 2 of 3 enumerated defects (static
prediction)" on every rating, and its own sentence for the reasoned-empty case.

**Recommendations are uncovered defects.** `TestRecommendation.defect_id` and
`UnobtainedRecommendation.defect_id` are required, so #283's untraceable shape
does not typecheck; `uncovered_defects()` never yields a defect a verdict says a
test kills, so #250 and #287's prescribe-what-exists cannot be composed at all.
`plausible_defect` is copied from the record rather than restated by the model,
which also drops a field from the response. The stage batches at 10 defects per
call, because the unit got smaller and #314's Gate 2 enumerated 75 for one review.

**Retired:** `evidence/mapping.py`, `discrimination.py`, `strength.py`,
`anchoring.py`, `rejudge.py`, `weak_patterns.py` and their tests, plus
`BlockKind.CHANGED_CODE`, which only the discrimination stage produced.

**The rating carry went with them.** DR-312 decision 6 already put the class in
its "always recomputed" row; #292's anchoring existed to stop a re-asked judge
moving a rating, and nothing is re-asked. Recorded in DR-312.

**`evidence/extraction.py` survives**, because the declaration comparison reads

**The batch-size control moved with its stage.** `--mapping-batch-size` became

A flag that accepts a value and reaches no stage is worse than no flag.

**Every stage reported 0.0% cached.** The shared message prefix is fine —
messages[:2] of a pair call is ~1,544 tokens, clear of OpenAI's 1,024 floor, and
takes 6-7 distinct values across 1,762 calls, so #314's defect-block move works.
What defeats it is a unique response schema per call: 1,762 distinct across

stage constrains some id per call, which is why all seven read 0.0%.

Not fixed here, deliberately: removing that constraint can cost recall, and the
response-shape pilot is the instrument that should settle it. Queued with the
pilot arm as its first task.
