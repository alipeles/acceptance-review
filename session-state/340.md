## What #340 does, in one paragraph

Where a candidate test **failed** under an injected edit, the tests that went on
**passing** under that same edit are not put to the model. The ones that failed
still are, because a red test does not on its own say the named defect is what it
caught. An edit nothing failed under skips nothing. **Rule 6**, the human's
addition: a defect whose judged pairs yield no kill has its held-back pairs
judged after all, before its rating is derived. A dropped pair is recorded as
`UnjudgedCause.PASSED_UNDER_EDIT`, derives no verdict, and raises the criterion's
`unknown` count. `ExecutionSettings.route_pairs` is on by default, and
`decide_execution` now runs the project's tests whenever **either** consumer
wants them.

## It shipped below its bar, deliberately

**Measured saving: about 9%. #340 asked for 80%.** It was merged on the human's
decision with the shortfall stated in the pull request, not because it passed.
Gate 2 was never clean.

Why, largest reason first:

1. **Only a killed defect can drop anything** — 13 of 68 attempts were kills.
2. **The edit builder fails most of the time.** Of 37 refused edits examined,
   **23 (62%) returned the code unchanged** and 9 (24%) did not parse. That is
   #334 and #338's work.
3. **This repository depresses the figure and no client repository would.** 19
   attempts came back `not_attempted` — *"no test went red, but 115 of 277 did
   not complete under the mutant"*. About 50 of our own tests re-enter the
   acceptance tool and start a nested pytest run, so mutating the tool makes them
   hang rather than fail. **The reviewing tool itself is not mutated**;
   `mutated_copy` applies the edit only to a throwaway copy. I verified that.
4. **The large saving belongs to #335.** A *verified* attempt settles its defect
   and `remaining_defect_sets` drops it from the judge entirely — for a survival
   as much as for a kill. Routing can only ever drop the non-killing tests of
   defects that were killed.

Full detail: `dogfood-logs/340-gate2-run1/judgement.md` and
`dogfood-logs/340-gate2-run2/judgement.md`.

## The one thing not finished

Branch `edit-results-never-reach-a-prompt`, **uncommitted and unpushed**. It adds
`tests/test_edit_results_never_reach_a_prompt.py`: eight assertions that what the
tests did *under an injected edit* reaches no model request, no persisted review
state and no rendered report, in both the verified and unverified cases.

Found by #340's own Gate 2, against my own code. The human agreed it is a remote
risk and asked for it anyway, on a separate branch, because the failure would be
silent.

**It is not a test that passes by construction.** I injected the leak — made a
killed attempt carry the failure text in its `reason` — and four of the eight
assertions failed, over review state and the report, in both modes. Then I
reverted and they passed. The pre-existing guard,
`test_the_static_judge_is_told_nothing_about_the_edit`, did **not** fail on that
injection, which is the gap this closes: it looks for one fixture's literal edit
text and the words "killed" and "injected", and failure output produced under an
edit contains none of them.
