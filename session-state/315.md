## The #314 seam — read before coding

#315 scores two things that #314 produces and that do not exist yet: the
predicted kills for each defect, and the test→defect edges the split metric is
recomputed over. The issue says #315 runs parallel to #314 and should land
first, so the resolution is to **take both as plain inputs rather than import
anything from #314**:

```python
PredictedKills = dict[str, set[str]]   # defect id -> pytest node ids predicted to fail
```

#314 fills it; #315 only scores it. Where nothing supplies it the metric reports
**absent, not zero** — the same discipline `expected_type` already follows in
`case.py`, where silence is not agreement. This is the one interface later work
depends on, so changing its shape is a decision, not a refactor.

## Plan

1. **`src/acceptance/benchmark/case.py`** — a `GroundTruthDefect` model (id,
   `obligation_id`, `type: DefectType` with `other` allowed, description,
   `killed_by: list[str]` of pytest node ids), a `defects` list on
   `GroundTruthLabels`, and `no_plausible_defect_reason: str | None` on
   `GroundTruthObligation` so a criterion with nothing plausible to record stays
   distinct from one the labels are silent about. `_check_tree_integrity` gains:
   unique defect ids, `obligation_id` resolves, and every `killed_by` entry
   appears in the union of the case's `candidate_tests`. An empty `killed_by` is
   valid and meaningful — archetype 04 is the case where nothing kills the
   defect.
2. **New `src/acceptance/benchmark/defect_scoring.py`** — a defect aligner in
   the shape of `alignment.py::align_obligations` but with its own prompt
   (that one is written for acceptance criteria and would be misapplied, exactly
   as `case.py` already notes for open questions); then enumeration recall per
   `DefectType`, type agreement over matched pairs only, the `other` share, and
   kill-prediction agreement. Recall and kill agreement are computed by separate
   functions over separate denominators — the separation is what #252 is about.
3. **`src/acceptance/benchmark/twin_splitting.py`** — a second entry point
   computing the existing split measure over supplied test→defect→obligation
   edges, alongside the existing report-parsing one.
4. **`tests/fixtures/archetypes/*/labels.json`** — defect labels for the §13.5
   scenario cases. These are the `human-gate` part: they need review before
   they are trusted, and archetype 04's on-point defect (a hard-coded `price/30`
   that a 30-day-month test cannot distinguish) is already described in its
   `evidence_rationale`, so several labels are transcriptions rather than new
   judgements.
5. **`tests/benchmark/`** — the eight completion expectations, including the
   hand-computed synthetic set and an assertion that scoring makes no live call.

## Risks

- **Label quality is the deliverable.** A wrong label is worse than no label,
  and never gets fixed to move a metric (*Working agreement* §3).
- **The aligner is a model call inside a measuring instrument.** It must be
  scored on the synthetic set like everything else, or it becomes an unmeasured
  component in front of the metric — the objection #314's issue raises against
  building reachability.
- Gate 2's "clean or stop" rule is suspended until #316 lands; run `check` once,
  fix what it genuinely finds, and record the result either way.
