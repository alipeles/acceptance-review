## Plan

New package `src/acceptance/execution/`. Nothing existing is rewired: nothing in
`src/acceptance/` references `Component.COVERAGE_RUNNER` or
`Component.MUTATION_RUNNER` today, so there is no execution code to integrate
with yet.

- `execution/outcome.py` — the typed per-test outcome and its five kinds, with a
  reason required on every kind that is not a completed run.
- `execution/sandbox.py` — the runner. One pytest subprocess over the named node
  ids, built from an allowlisted environment rather than an inherited one, with
  a per-test budget and a whole-run deadline. Returns outcomes; never raises out.
- `execution/netblock.py` — the module injected on `PYTHONPATH` that installs
  the socket-level block before pytest collects anything.
- `execution/config.py` or fields on `RunConfig` — budgets and interpreter path
  as configuration with conservative defaults.

## Decisions this plan makes, which the issue does not

- **The network block is at the Python socket layer, not the operating system.**
  There is no portable way to get an OS-level network namespace on macOS without
  privileges. The limit is real and should be stated in the docs: a C extension
  opening a socket without going through Python's `socket` module is not caught.
- **One pytest subprocess for the whole named set, not one per test.** Per-test
  isolation would make the per-test budget trivial but costs a process start per
  test. The per-test budget is enforced inside the subprocess instead; the
  whole-run budget is a wall-clock kill of the process group from outside.
- **Nothing is wired into the verdict.** Tier elevation belongs to #42 (M8.1,
  the feasibility probe) and #44 (M8.3, the coverage-confirmed tier), and this
  task file's scope exclusions say so. The three `task-03` obligations are
  demonstrated at the runner's contract: it returns on every failure path rather
  than raising, so no caller can be made to fail by a run that did not complete.
