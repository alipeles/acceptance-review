## What was built

`recommend_tests` no longer raises on omission. It returns a
`RecommendationResult` (prescriptions + not-obtained), marks the omitted
obligations indeterminate via `UnusableAnswerLog.mark_indeterminate`, and the
pipeline re-applies `_apply_indeterminate` **after** the stage — the existing
pass runs at strength time, so without the second one the mark never reaches the
obligation and the verdict could come back clean. `Review.unobtained_recommendations`
persists it; the report renders `NOT OBTAINED` where the prescription would be,
distinct from the `not required` line; `acceptance recommendation --criterion`
returns the record rather than None. Duplicate and unsupplied ids still raise.

**No transcript re-record was needed** — the prompt, schema and supplied ids are
unchanged, so the stage's request key did not move.

Defect injection confirms both mechanisms are load-bearing: removing the second
`_apply_indeterminate` fails 2 tests, removing the report block fails 2 others.
