## The one thing not to get wrong

**`carry_key` spreads `inputs` into the payload; it must not nest it.** Every
ledger entry on disk holds a key computed #269's way. Nest it and none of them
match, every requirement re-derives, and #269's churn returns **while the feature
still looks like it works** — nothing fails, runs just quietly get worse.

Pinned by `test_moving_the_rule_left_the_decompose_carry_key_byte_identical`,
which asserts the literal `8e27b8094d97e9b3c1a7c3133e9c6641981198dd2b7f530d7f1b35f1e79fba01`
computed from #269's payload by a separate script. **Golden value, not
recomputed** — a test that recomputed it would agree with any change that broke
it.

## Do not rediscover

- **`git switch -C <name> origin/main` fails in this worktree**: it writes
  upstream config to the *primary* worktree's `.git/config`, which the sandbox
  denies — and the switch is left **partway done**, with the index holding the
  other branch's tree while `HEAD` stays put. Recover by backing up your
  uncommitted files first, then `git reset --hard HEAD`. Use the two-step
  `git branch --no-track <name> origin/main && git switch <name>` instead, which
  writes no config. This is a fourth variant of `CLAUDE.md`'s sandbox trap and
  the failed command still creates the branch, so a retry hits
  "a branch named X already exists".
- **`session-state/*.md` is committed on `main`, not on a branch.** Switching
  branches deletes it from the working tree. Restore with
  `git show origin/main:session-state/<n>.md > session-state/<n>.md`.
- **The formatter hook strips an import** whose only usage an edit briefly
  removed. It bit once in `tests/test_carry.py`.
