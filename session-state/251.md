## What already exists, and what #251 actually changes

The carry-forward machinery is already there and already wired:
`rerun.py::obligations_to_rederive` filters which obligations reach mapping and
discrimination, and `merge_carried_forward` splices the prior judgements back
(`pipeline.py:303` and `:380`). #251 is two changes to it.

**Deliverable 1 — narrow the staleness predicate.**
`rerun.py::stale_obligation_ids` marks an obligation stale when any *file* it
cites was touched. That is the exact defect in #251's comment: nine tests appended
to one module re-opened every obligation citing that module, and 33 came back a
tier lower. Replace the test half with a content comparison over the mapped tests
themselves, and store a per-obligation dependency digest (requirement text, sorted
mapped test node ids, digest of each mapped test's source) in review state.

Note the predicate currently gates the whole obligation — coverage status *and*
evidence rating. #251 is about the rating, so it likely has to split into two
predicates. That is the main structural decision in the implementation.

**Deliverable 2 — the justification constraint.** `evidence/discrimination.py`
gains, per criterion, the stored rating and a typed list of that criterion's
dependency changes, plus a `rests_on` field naming one of them. Enforcement is
`supplied_ids.constrain`/`scan`/`UnusableAnswerLog`, which already exists to
reject an answer naming an id it was not given, and whose
`unusable_answer_finding` is the "a rejected judgement is reported" half.

Files expected: `rerun.py`, `review_state.py`, `evidence/discrimination.py`, a
new dependency-digest module under `evidence/`, `pipeline.py`, `report.py`, and
tests.

## The one design decision to settle

"The set of tests mapped to it" is ambiguous between the *prior* mapped set and
the set mapping returns *this* run.

- Compare against the prior set only: fully insulated from #182, but a newly
  added test supporting a criterion is never credited, so the gate becomes
  unchaseable in the opposite direction from today's.
- Run mapping every run and compare membership: credits new evidence, inherits
  #182's instability as spurious re-judges.

**Recommendation: the second.** Mapping is one batched call over the obligation
set, so skipping criteria saves little there, and #269's Gate 2 is the evidence
that closing a gap must be able to *raise* a rating. Deliverable 2 is then what
keeps #182's instability from moving ratings: a spurious mapping change causes a
re-judge, but the rating still cannot move without naming a real change.
