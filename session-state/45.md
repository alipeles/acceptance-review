## What #45 asks for, after the 2026-09-14 revision

Read the issue; it was rewritten the same day. The short version: inject the
named defect, run the candidate tests against the mutant, and let the result
stand as an observation. **Injection runs before the static pair judgement**,
which then runs only on the remainder. That ordering is the point — the static
pair stage cost $6.02 of the $6.87 in #316's Gate 2 review.

Acceptance is `tests/fixtures/archetypes/03-superficial-test`, whose
`labels.json` already records the `killed_by` ground truth: `d-interest-ignored`
and `d-payments-not-equal` survive every candidate test, `d-one-entry-short` is
killed by `test_loan.py::test_returns_a_payment_for_each_month`. Both outcomes
must be reproduced, and the tier upgrade must be visible in the pipeline's own
output rather than only in a unit test of the runner.

## The design, and where it is written down

`docs/DR-171-mutation-targeting.md`, revised 2026-09-14 (landed at `61c5a3c`).
Decisions 1, 2 and 5 stand from the original; 3, 4, 6, 7 and 8 changed.

- **Decision 7** — `judge_pairs` in `pipeline.py::run_review` moves *after* the
  mutation stage and runs on the remainder. This is the change that saves the
  money.
- **Decision 4** — coverage is not the selector. The mutant runs against every
  candidate test; which tests go red is the mapping. Coverage missed 43 of 268
  recorded kills when measured, so it survives only as an optional narrowing for
  slow suites, and what it excludes is undecided, never reported as uncovered.
- **Decision 6** — a candidate test red at head halts the review by default,
  with an override. Falling back to static judging costs more than stopping.
- **Decision 3** — non-Python files are mutable; the `ast.parse` check applies
  only where there is a parser.
- **Decision 8** — the `unreached` outcome is withdrawn. `not_mutable` and
  `not_attempted` are routing instructions to the static judge, not conclusions.

**§8.2 of the spec was amended** to drop "runs only the handful of mapped tests"
and "not a combinatorial explosion". §1 principle 6 and §17 are untouched: the
candidate set is a targeted subset and the full suite is still never run.

**#45 no longer depends on [#44](https://github.com/alipeles/acceptance-review/issues/44)**
(M8.3, the coverage-confirmed tier). It needs only the per-test baseline, which
it takes itself. #44's coverage map is an optimization that can follow.

## What #43 already built, which this sits on

`src/acceptance/execution/`, landed at `75fb5d7` (PR #332). Standalone: nothing
elevates a tier through it.

- `run_tests(test_ids, project_root, config) -> SandboxRunResult` in
  `sandbox.py`. One pytest subprocess over the named node ids, new session,
  allowlisted environment, process-group kill on the run-wide budget. **It
  returns on every failure path rather than raising** — that contract is tested,
  and callers depend on it.
- `TestOutcomeKind` in `outcome.py`: `passed`, `failed`, `network_blocked`,
  `timed_out`, `not_started`. Every outcome that is not a completed run carries a
  reason, enforced by a validator.
- `SandboxConfig`: `interpreter`, `per_test_seconds` (30), `total_seconds` (300).

**The mutation runner is the first thing that will elevate a tier.**
`evidence_tier.py::authorize_tier` already makes `Component.MUTATION_RUNNER` the
only component allowed to produce `DEFECT_KILLED`, and nothing uses it yet.

attempt of all three Gate 1 runs. The empty run still makes and records its model
calls, which is why every re-run reported 0 live calls and $0 spent. `CLAUDE.md`
documents this; check `wc -c` after every redirect.
