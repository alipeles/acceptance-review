## What changed on 2026-09-14, and why it matters more than anything else here

The human asked why the execution tier could not replace the expensive static
pair judgement rather than sit on top of it. It can, and
`docs/DR-171-mutation-targeting.md` (the record on how a named plausible defect
becomes a mutation at exact lines) was revised accordingly. Decisions 1, 2 and 5
stand; 3, 4, 6, 7 and 8 changed.

- **Decision 7 is the one that matters.** It used to say injection "overwrites"
  static verdicts, which means paying for all 23,808 pair judgements and then
  discarding some answers. Now `judge_pairs` in `pipeline.py::run_review` moves
  *after* the mutation stage and runs only on the remainder.
- **Decision 4: coverage is no longer the selector.** The mutant runs against
  every candidate test; which tests go red *is* the mapping. Coverage was
  measured to miss 43 of 268 recorded kills, and under the old design those
  became reported findings. Coverage survives only as an optional narrowing for
  slow suites, and what it excludes is undecided, never reported as uncovered.
- **Decision 6: a red candidate test halts the review by default**, with an
  override. Falling back to static judging costs *more*, not less.
- **Decision 3: non-Python files can be mutated.** The `ast.parse` check applies
  only where there is a parser. Documentation defects are killed by tests that
  read the file.
- **Decision 8: the `unreached` outcome is withdrawn.**

**§8.2 of the spec was amended** to drop "runs *only the handful of mapped
tests*" and "not a combinatorial explosion" — they assumed the mapping stage
#312 and #316 deleted. §1 principle 6 and §17 are untouched: candidate tests are
a targeted subset and the full suite is still never run.

**The sequencing inverted: #45 no longer depends on
[#44](https://github.com/alipeles/acceptance-review/issues/44) (M8.3, the
coverage-confirmed tier).** #45 needs only the per-test baseline, which it takes
itself. #44's coverage map becomes an optimization that can follow.

## What DR-171 decided, so it is not re-litigated

Read the record itself; this is the index, and the revised decisions are marked.

- **Decision 1:** the mutation descriptor is produced at M8.4. The enumeration
  stage's output shape does not change.
- **Decision 2:** the descriptor is one contiguous span replacement, inside the
  defect's own region.
- **Decision 3 (revised):** validity is four mechanical checks and **no
  confirming model call**. The parse check applies only to files with a parser,
  so non-Python files are mutable.
- **Decision 5 (amended):** a survival stays a finding. Blind tests are no longer
  split off beforehand, so they land here — and the finding is the same either
  way: no test the builder wrote catches this defect. The causes differ in the
  remedy, not the verdict.
- **Decision 7 (revised):** one `PairVerdict` record carrying a tier, so the
  static path stays and the rating has one implementation. `PairVerdict` gains a
  tier field; a pair-judgement verdict is `STATIC`, a mutation-runner one is
  `DEFECT_KILLED`. `defects/support.py` currently hardcodes `EvidenceTier.STATIC`
  as the achieved tier for every criterion and becomes the weakest tier among
  the verdicts the rating actually rests on. **The static judge now runs on the
  remainder, after injection, not first.**
- **Decision 8 (revised):** every attempt gets a typed outcome — `killed`,
  `survived`, `not_mutable`, `not_attempted` — and the last two must carry a
  reason and are routing instructions to the static judge, not conclusions.

## What DR-171 measured that injection cannot reach

From `docs/experiments/coverage-prefilter/FINDINGS.md`, over #316's Gate 2 review
at head `3e1d3a9`, 48 defects and 496 tests:

- **Nine of the 48 defects had no usable code region at all**: seven named
  module-level regions, one a non-Python file, one lines that never execute.
- **Tests that fail through file reads rather than execution.** Tests asserting
  on README and decision-record text kill documentation defects without executing
  the implicated code. Line coverage cannot see that channel and neither can a
  line-level mutation.
- **Absence defects.** For `not_wired`, `documented_not_implemented` and
  `missing_case`, the implicated lines are where behaviour *should* be, and a
  test can fail on the absence through code that lives elsewhere.

#43 could not reach a clean Gate 2 and was merged on an explicit human decision.
The cause is now filed as
**[#333](https://github.com/alipeles/acceptance-review/issues/333)**: a defect no

`defects/support.py::_class_for` reaches `strongly_supported` only when
`covered == enumerated`. The existing `no_plausible_defect` outcome only covers a
criterion with **zero** enumerated defects.

That will bite any mandate with a stated platform limit. Budget for it: a
not-clean Gate 2 may be the honest result again, and the decision to proceed is
the human's each time.

## This repository supplies counterexamples, never thresholds

It is the easy case: hermetic, about five minutes, no services, no credentials,
no UI, no build step, and none of the four classes §8.3 names as infeasible. It
can disprove that a proposed rule always works; it cannot say where a rule should
say no. Every number this milestone needs is configuration with a conservative
default.
