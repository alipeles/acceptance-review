## What DR-171 already decided, so it is not re-litigated

- **Decision 1:** the mutation descriptor is produced at M8.4. The enumeration
  stage's output shape does not change.
- **Decision 2:** the descriptor is one contiguous span replacement, inside the
  defect's own region.
- **Decision 3:** validity is four mechanical checks and **no confirming model
  call**.
- **Decision 5:** the ambiguous outcome is a surviving mutant on executed lines,
  and it stays a finding.
- **Decision 7:** one `PairVerdict` record carrying a tier, so the static path
  stays and the rating has one implementation. `PairVerdict` gains a tier field;
  a pair-judgement verdict is `STATIC`, a mutation-runner one is
  `DEFECT_KILLED`. `defects/support.py` currently hardcodes `EvidenceTier.STATIC`
  as the achieved tier for every criterion and becomes the weakest tier among
  the verdicts the rating actually rests on.
- **Decision 8:** every attempt gets a typed outcome — `killed`, `survived`,
  `unreached`, `not_mutable`, `not_attempted` — and the last two must carry a
  reason.

## What DR-171 measured that injection cannot reach

From `docs/experiments/coverage-prefilter/FINDINGS.md`, over #316's Gate 2 review
at head `3e1d3a9`, 48 defects and 496 tests:

- **Nine of the 48 defects had no usable code region at all**: seven named
  module-level regions, one a non-Python file, one lines that never execute.
- **Tests that fail through file reads rather than execution.** Tests asserting
  on README and decision-record text kill documentation defects without executing
  the implicated code. Line coverage cannot see that channel and neither can a
  line-level mutation.
- **Absence defects.** For `not_wired`, `documented_not_implemented` and
  `missing_case`, the implicated lines are where behaviour *should* be, and a
  test can fail on the absence through code that lives elsewhere.
