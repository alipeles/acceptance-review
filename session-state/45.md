## The defect that voided three runs

Tests running in the copied project imported the code from the **original**
tree. A project installed into its environment — `pip install -e .`, the normal
way a `src/` layout is set up — resolves imports through an absolute path
recorded at install time, and copying the tree does not change that.

So every mutant had no effect, every defect was reported as *survived*, and the
review would have told the builder their tests were weak about code it never
altered. Fixed by putting the copy's root and `src/` on `PYTHONPATH` ahead of
site-packages. Verified both ways: a mutant removing a `raise` now fails the test
asserting that `raise` and passes at head.

This is generic, not a quirk of this repo, and it is the single most important
thing on this branch.

## The evidence-tier aggregation is wrong (human's correction, 2026-09-15)

There are **two different aggregations** and `defects/support.py` uses the same
one for both:

- **Across tests for one defect: take the best.** One test that fully covers a
  defect makes it covered. A defect killed by an executed verdict is
  `DEFECT_KILLED`, and another test judged only by reading must not drag it down
  to `STATIC`. Today `tier_by_defect` takes `min` over every verdict regardless
  of whether it kills. **This is a bug.**
- **Across the defects of a criterion: take the worst.** Part strongly covered
  and part weakly covered means weakly covered. This one the code gets right.

Fix: a defect's tier is the **maximum** tier among its *killing* verdicts when
it is covered; the minimum across all its verdicts when it is not. Then minimum
across the criterion's defects, unchanged.

## Agreed next step, not yet built

**Make the decline reason a typed, schema-constrained field on the descriptor
response**, with three values: the defect is already true of the code; the
defect is not a property of any code span; it cannot be expressed as one
contiguous edit. Today all three arrive as one sentence and cost a human read to
tell apart.

This is additive by design — the defect still goes to the static judge exactly
as now, so no rating arithmetic moves. It gains:

- the **already-true** case as a reported finding, flagged as needing human
  review (it is the strongest claim the tool makes: not "your tests are thin"
  but "your code is wrong");
- the **not-a-code-property** case identified, which is what should leave the
  denominator — that arithmetic is #333, already filed;
- pressure against the fourth, unnamed case: a model that must pick a category
  cannot hide "I gave up" in a generic sentence.

Also narrow the prompt: decline only when the defect is a true statement about
the code right now, not when the edit is merely awkward.

Size: one response field, two outcome kinds, a report block, tests. Re-records
the 71 descriptor calls (~$0.26) and needs one ~10-minute run to verify.

**Then, and only then, try a stronger model than `openai/gpt-5.4-mini` on the
descriptor stage.** One variable at a time. The case for it: 30% no-op rate
before the prompt change, and unparseable Python on another 8%.
